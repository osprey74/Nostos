# 電波法・技適コンプライアンス（厳守事項）

> 🔴 **本プロジェクトは日本の電波法を絶対に順守する。以下のガードレールは"努力目標"ではなく厳守事項である。**
> 送信を行うファームウェア（C6L ビーコン、および将来 PaperMono を送信に使う場合）は、
> **すべて認証された無線特性の範囲内に固定**すること。逸脱の可能性がある変更は実装・運用しない。

最終更新: 2026-09-10 ／ 根拠: 各機の技適（工事設計認証）・M5Stack 公式 AI 回答・総務省の一般則。

## 0. 大原則

- **受信は技適・免許の対象外**（受信設備は無線局でない）。→ **PaperMono は受信専用に保つ限り、送信の技適論点は生じない。**
- **送信の技適論点は送信側（C6L／ビーコン）に集中する。** 送信は必ず技適済み機体で、認証範囲内でのみ行う。
- **ハード能力 ≠ 認証範囲。** SX1262 は 868〜923MHz・最大 +22dBm を物理的に出せるが、**合法枠は下表の認証プロファイルのみ**。データシートの能力で運用してはならない。
- **SDR 的設計の注意（総務省の考え方）**: 無線特性をソフトで変更できる機器は、**RF 特性を変えるソフトも認証の対象**として扱われる。したがって **RF パラメータは"自由に変更できる作り"にせず、認証枠にハードコード固定**する。

## 2. 送信ファームウェアのガードレール（ハードコード必須）

| # | 項目 | 厳守値 | 理由 |
| --- | --- | --- | --- |
| G1 | **送信中心周波数** | **922〜923.4 MHz 内に固定**（Nostos 既定 923.000 MHz） | 認証帯域内 |
| G2 | **占有帯域**（LoRa BW） | **≤ 200 kHz**（Nostos 既定 125 kHz） | 認証の 200kHz 以下 |
| G3 | **送信出力** | **≤ 5.0 mW（≈+7dBm）**（Nostos 既定 +6dBm≈4mW） | 認証上限。**+22dBm に上げない** |
| G4 | **国外帯域の送信** | **868MHz 等の送信パスを無効化** | EU 帯・日本で不可 |
| G5 | **占有帯域の端** | 中心 ± BW/2 が **922.0〜923.4 MHz を超えない** | 帯域端も認証内に収める |
| G6 | **アンテナ** | **純正（内蔵）アンテナのまま**。高利得等に交換しない | アンテナ込み認証 |
| G7 | **LBT／デューティ** | **毎送信の前に RSSI キャリアセンス**（ARIB STD-T108）。**閾値 -80dBm・窓 ≥128μs**。適応間隔（移動=最短30s／停止=10分）＋ボタン任意発信で送信量を最小化 | 特定小電力の要件。実装: `firmware/c6l-beacon/src/main.cpp` |
| G8 | **受信専用の堅持** | PaperMono は**送信コードを持たせない／有効化しない** | 受信は対象外＝安全 |

これらは `crates/nostos-frame` の `radio` モジュールに**定数＋コンパイル時アサーション**として実装し、
逸脱値ではビルドが失敗するようにしている（G1/G2/G3/G5）。**定数を緩める変更は本ドキュメントの更新と再確認を伴うこと。**

## 2.5 ARIB STD-T108 v1.5 確定パラメータ（一次情報・確実性 高）

英語版原典（2023-03 v1.5）で確認。C6L は **20mW 以下・キャリアセンスあり（Part 2）**カテゴリで運用する前提。

- **単位チャネル**: 200kHz 間隔・帯域 200kHz。**ch36 = 923.0 MHz**（Nostos 既定送信＝正規チャネル）。ch24-32 と ch33+ の同時使用禁止（単一 ch では無関係）。
- **キャリアセンス（§3.4.2）**: 時間 **≥128μs**、レベル **-80 dBm**（受信電力が -80dBm 以上なら送信禁止）。**出力が 20mW 超なら閾値をさらに下げる**が、Nostos は ≤5mW なので -80dBm のまま。CS 帯域 = 200×n kHz（n=1 → 200kHz）。
- **送信時間制御（§3.4.1(2)・922.4〜928.0MHz・1ch）**: 連続送信 **<400ms**、時間あたり総量 **≤360s**、休止（送信 6〜200ms なら **2ms**）。Nostos はエアタイム ≈165ms（SF9）・毎分1回以下で桁違いに余裕。
- → **既存のハードコード値（-80dBm / 128μs / 923.0MHz / <400ms）は原典と一致。確実性 高。**

### 方式の決定: **LBT（キャリアセンス）方式のみ採用**（LDC 不採用）

原典 Part 3 には LDC（Low Duty Cycle）方式＝キャリアセンス不要の区分もあるが、**本プロジェクトでは採用しない**。
**毎送信の前にキャリアセンス（-80dBm / ≥128μs）を行う LBT 方式（Part 2）で統一する。** 理由：最も保守的で、
C6L の認証カテゴリ（Meshtastic 由来＝CS 方式の公算大）と整合し、実装・検証も済んでいるため。
FH 方式も同様に不採用（周波数ホッピング必須で単一周波数ビーコンに不適）。

### 実機検証（2026-09-10・C6L ビーコン）

- **実装**: RadioLib `radio.getRSSI(false)`（=GetRssiInst 瞬時 RSSI）を `startReceive` 後に読み、-80dBm と比較。
  ※`getRSSI(true)` は last-packet RSSI で未受信時に無効値(-0.5)を返す罠。**必ず `false`**。
- **挙動**: 机上（NAS/UPS/Mac 等の近く）はフロア ≈-76dBm → **正しく送信保留（busy）**。
  窓際(3.5m 離隔・充電器給電)はフロア < -80dBm → **送信（LBT free）→ PaperMono が受信**（RSSI-85/SNR10/len16）。
- → **混雑チャネルでは送らず、クリーンなら送る＝ARIB §3.4.2 どおりに機能することを実機確認。** CAD 方式は不採用。
- 送信成功時にブザー通知（`PIN_BUZZER`）。BW125 の真の雑音床は約 -117dBm なので、卓上の高フロアは近接電子機器/給電由来。

## 3. 変更管理

- 周波数・帯域・出力・変調・アンテナのいずれかを変える場合は、**必ず本ドキュメントを先に更新**し、認証範囲内であることを再確認してから実装する。
- Meshtastic 既定 JP LongFast（923.375MHz / BW250）は占有上端 ≈923.5MHz で **G1/G2/G5 を外れ得る**。Nostos-native 送信では**採用しない**（自前の 923.000MHz / BW125 を用いる）。

## 4. 確認先・免責

- **最終的な合法性判断は、総務省の公式見解と各機の認証書類に基づく。** 本ドキュメントは設計上のガードレールであり、法的助言ではない。
- 疑義がある場合は M5Stack サポート／総務省 電波利用ホームページ（技適検索 https://www.tele.soumu.go.jp/giteki/SearchServlet ）で確認する。
- M5Stack 公式 AI 回答（2026）: 「**認証された無線特性の範囲内に収めた自作ファームなら、焼いただけで技適対象外にはならない**」。ただし SDR 的設計の注意（§0）を伴う。

## English summary

Nostos strictly complies with Japan's Radio Act. Transmitting firmware (the C6L beacon) **must** stay within the certified RF envelope of each device:

- **Unit-C6L (Giteki 211-250603): F1D, 922–923.4 MHz, 1.5–5.0 mW.**
- **PaperMono (211-260514): F1D, 922–923.4 MHz, ~1 mW** — used **receive-only** (RX is outside Giteki scope).

Hard guardrails (hardcoded, compile-time enforced in `crates/nostos-frame::radio`): TX center 922–923.4 MHz (default 923.000), bandwidth ≤ 200 kHz (default 125 kHz), power ≤ 5.0 mW (default +6 dBm), occupied band within 922.0–923.4 MHz, 868 MHz TX path disabled, stock antenna only, ARIB STD-T108 LBT/duty. Final legality rests on MIC (総務省) guidance and the certification documents.
